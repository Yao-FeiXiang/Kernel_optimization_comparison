# 简化默认基准命令设计

## 目标

让最常用的完整实验只需要：

```bash
python3 benchmark.py --all --update-results
```

该命令默认采用当前 A100 教程对比口径，并确保执行的是最新源码构建出的程序。其他尺寸、方法和计时参数继续通过现有 CLI 选项显式覆盖。

## 默认行为

Python 入口的默认参数改为：

- `M=N=K=4096`
- `warmup=5`
- `repeat=50`
- `alpha=0.8`、`beta=0.2`、`seed=42` 保持不变
- 直接 NVCC 构建继续默认使用 `sm_80`，并允许 `SGEMM_CUDA_ARCH` 覆盖

只修改用户推荐的 Python 入口和其 `NativeRunOptions` 默认值。原生 `sgemm_bench` 的轻量默认值保留，避免直接调用原生程序时意外启动耗时的完整实验；Python 始终把最终参数显式转发给原生程序，因此两者不会产生含糊行为。

## 自动构建新鲜度

默认运行时，`build_executable` 比较现有可执行文件与以下构建输入的修改时间：

- 注册在 `PHASE_A_SOURCES` 中的 CUDA/C++ 源文件
- `include/` 下的公共头文件
- `CMakeLists.txt`

如果可执行文件不存在或早于任一构建输入，则自动重新构建；否则复用现有程序。这样源码更新后，简短默认命令不会静默运行旧内核。

显式指定 `--no-build` 时保持“禁止构建”的语义：程序不存在或已经过期都直接报错，并提示去掉 `--no-build` 或使用 `--build`。`--build` 始终强制重新构建。

## 参数覆盖

现有参数不改名、不删除。用户可以按需覆盖默认值，例如：

```bash
python3 benchmark.py --kernel 10 --m 2048 --n 2048 --k 2048 --repeat 20
```

显式参数优先于默认值。`--update-results` 仍由用户明确添加，不改成无条件写文件。

## README 精简

README 保留项目目的、方法列表、默认口径、结果表说明和必要环境信息，但把命令示例压缩为四类：

1. 默认完整实验并更新结果。
2. 单方法或自动调优。
3. 手动覆盖尺寸/轮数。
4. 小尺寸正确性检查。

CMake、底层添加 kernel、重复构建示例等细节移出主流程或压缩成简短文字。README 中最多保留六个 shell 代码块，首屏直接展示默认命令。

## 结果文件处理

当前工作区中的 `RESULTS.md` 是用户刚运行默认命令产生的改动，必须保留。由于该运行复用了旧可执行文件，实现完成后会用新鲜构建显式重跑 1024 配置，纠正该实验组中的旧 variant/configuration；已有 4096 正式实验组继续保留。

## 测试

测试先固定以下行为：

- Python `--all` 默认解析为 4096、5 次预热和 50 次计时。
- 显式尺寸和轮数能覆盖默认值。
- 构建输入比可执行文件新时判定为 stale；反之可复用。
- `--no-build` 遇到 stale 可执行文件时返回错误。
- README 包含简短默认命令，且 shell 代码块不超过六个。
- 结果更新仍保留 1024 与 4096 两个实验组。
