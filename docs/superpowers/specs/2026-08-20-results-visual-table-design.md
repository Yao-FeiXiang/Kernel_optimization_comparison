# SGEMM 结果可视化表格设计

## 目标

让每次带 `--update-results` 的基准实验自动更新 `RESULTS.md` 中的可视化性能排行，不要求用户再手工整理数据。普通实验不写结果文件。

## 方案选择

采用增强现有明细表的方案，而不是替换为缺少诊断字段的精简表，也不额外生成一张重复的排行表。每个实验分组仍只保留一张 Markdown 表格，并继续保留配置、延迟、GFLOP/s、误差等现有信息。

## 渲染规则

- 每个实验分组独立排序。
- `status == "pass"` 的方法按 GFLOP/s 从高到低排列；同速时使用稳定的方法 ID 顺序。
- 通过的方法获得从 1 开始的排名；失败或不可用的方法置于末尾，排名显示 `—`。
- 表格加入 `Performance vs cuBLAS` 列，以最多 20 个 Unicode 实心方块显示相对 cuBLAS 性能，并附一位小数百分比。
- 性能达到或超过 cuBLAS 时，方块长度封顶为 20，但百分比保留真实值。
- 当前实验分组没有成功的 cuBLAS 记录，或 cuBLAS GFLOP/s 非正数时，该列显示 `—`。
- `vs Naive`、数值精度、变体和配置等现有字段继续保留。
- HTML 注释中的紧凑 JSON 记录不改变格式，确保历史记录仍可解析和重新渲染。

## 数据流

`benchmark.py --update-results` 解析本次原生 JSON 后，继续调用 `update_results_file()`。该函数合并相同实验键和方法 ID 的记录，再由 `render_results()` 对每个实验分组重新排序并生成完整表格。因此单方法更新和批量更新都会自动刷新可视化排行。

## 兼容性与错误处理

- 不新增命令行参数，也不改变实验键和覆盖规则。
- 旧 `RESULTS.md` 的内嵌记录可以直接升级为新表格格式。
- 不可用方法不显示虚假的数值或性能条。
- 文件仍通过临时文件原子替换，失败时不留下半张表。

## 测试

- 验证通过的方法按 GFLOP/s 降序排列并获得正确排名。
- 验证性能条和相对 cuBLAS 百分比正确生成。
- 验证超过 cuBLAS 的百分比不被截断，仅限制方块数量。
- 验证缺少 cuBLAS 或方法不可用时显示 `—`。
- 保留记录往返无损和结果文件幂等更新测试。
